# Integrate Dummy Image Assets & Motion — SCM Company Profile

## 1. Objective

Integrate the provided SCM dummy image assets into the existing Next.js + TypeScript (TSX) company profile website.

The goal is to replace empty image placeholders with appropriate temporary visuals, improve the page's visual hierarchy, and introduce subtle, professional animations.

The website belongs to PT. Sinlie Cahaya Matahari, an Indonesian sock manufacturing company.

Maintain the existing Modern Industrial Corporate design direction and established teal-yellow brand palette.

**Do not rebuild the project from scratch.** Inspect the existing implementation and improve it incrementally.

## 4. Image Rendering Requirements

Use Next.js `Image` from `next/image` for local image assets.

Requirements:

- Use valid local paths beginning with `/images/dummy/`.
- Set appropriate `width` and `height`, or use `fill` inside a correctly positioned container.
- When using `fill`, provide a parent container with `position: relative` and a defined aspect ratio or height.
- Use `sizes` for responsive images where appropriate.
- Use `object-cover` for cropped photography and `object-contain` for assets that must remain fully visible.
- Use meaningful alt text for content images.
- Use empty alt text for purely decorative images.
- Prevent layout shifts by reserving image dimensions.
- Use lazy loading for below-the-fold images.
- Do not lazy-load the main hero image if doing so would delay the primary visual content.
- Do not use CSS background images for content that needs meaningful alt text.

Avoid unnecessary image libraries or external image services.

## 5. Animation Direction

Animations should feel restrained, polished, and suitable for a B2B manufacturing company.

Use CSS transitions and Intersection Observer-based reveal effects only where useful. Prefer existing project utilities if they already provide this functionality.

### Initial Page Load

- Fade in the hero content.
- Reveal the hero image with a small vertical movement or subtle scale transition.
- Keep the duration around 400–700ms.
- Avoid long entrance sequences that delay access to the content.

### Scroll Reveal

For selected sections:

- Use a small upward movement, approximately 12–20px.
- Transition opacity from 0 to 1.
- Use a duration around 400–600ms.
- Apply a modest stagger to a small number of related cards.
- Trigger animations when elements enter the viewport.

Do not animate every paragraph and element independently.

### Product Cards

- Use a subtle image scale transition on hover.
- Keep transitions around 200–300ms.
- Use a restrained border or shadow change.
- Avoid continuous floating, pulsing, or bouncing.

### Buttons and Navigation

- Add smooth color transitions.
- Provide clear hover and keyboard focus states.
- Do not make the interface depend on hover to reveal essential information.

### Decorative Elements

- Use the existing teal and yellow colors.
- Keep abstract backgrounds subtle.
- Do not introduce large animated gradients or distracting moving patterns.

## 6. Motion Accessibility and Performance

- Respect `prefers-reduced-motion`.
- Disable nonessential reveal and transform animations when reduced motion is requested.
- Avoid large amounts of JavaScript for animation.
- Do not introduce a motion library unless the project genuinely needs it.
- Do not animate layout properties that cause unnecessary reflow.
- Prefer opacity and transform for animation.
- Avoid scroll event handlers that run continuously without a clear need.
- Ensure content remains visible and readable if animations fail or JavaScript is disabled.

If Intersection Observer is required, encapsulate the behavior in a reusable hook or small client component rather than duplicating the logic throughout the application.
